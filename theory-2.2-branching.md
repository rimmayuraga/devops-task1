# Теория для ментора — Task 2.2 (бранчевание)

## 1. Что такое коммит и какие данные он содержит?

**Коммит** — зафиксированный снимок состояния проекта. Содержит:
- ссылку на **дерево** (tree) — структуру файлов и каталогов на этот момент;
- ссылку на **родительский коммит** (или несколько — для merge);
- **автора** и **дату**;
- **сообщение** коммита.

Каждый коммит неизменяем: изменение содержимого порождает новый коммит.

## 2. Как Git создаёт хэши коммитов?

Хэш (SHA-1/SHA-256) вычисляется от содержимого коммита: дерево, родитель,
автор, дата, сообщение. Даже одно изменение даёт совершенно другой хэш.
Поэтому хэш однозначно идентифицирует коммит и его положение в истории.

## 3. Как просмотреть историю и хэши?

```bash
git log                     # полная история (хэши, авторы, даты)
git log --oneline           # короткие хэши + сообщения
git log --oneline --graph   # с графом ветвлений
git show <хэш>              # что изменил конкретный коммит
```

## 4. Что такое ветка и чем отличается от основной (master/main)?

**Ветка** — это **подвижный указатель** на коммит. Когда делаешь коммит в ветке,
указатель сдвигается на новый коммит. Ветки позволяют вести параллельную работу
(фичи, эксперименты), не трогая основную.

**Основная ветка** (`master`/`main`) — просто «главная» по договорённости ветка;
технически она ничем не отличается от других. `HEAD` — указатель на текущую ветку/коммит.

## 5. Как работает `.gitignore`?

Файл `.gitignore` содержит **шаблоны** путей, которые Git должен **игнорировать**
(не отслеживать): временные файлы, сборки, секреты, локальные данные.
Пример:
```
tmp/            # всю папку tmp и её содержимое
*.log           # все .log
.DS_Store       # системный файл macOS
```
Уже отслеживаемые файлы `.gitignore` не «разотслеживает» — нужно `git rm --cached`.

## 6. Как работает `.gitkeep`?

Git **не хранит пустые каталоги**. Чтобы «сохранить» пустую папку в репозитории,
в неё кладут пустой файл-заглушку, обычно `.gitkeep` (соглашение, не встроено в git).
Тогда папка появляется в репозитории.

## 7. Как правильно настроить `.gitignore`

- Шаблоны: `/build/` (только в корне), `tmp/` (папка в любом месте), `*.tmp` (по маске),
  `!important.tmp` (исключение из правила).
- Складывать в `.gitignore` стоит: зависимости (`node_modules/`), сборки (`dist/`),
  логи, IDE-файлы (`.idea/`, `.vscode/`), секреты (`.env`), системный мусор (`.DS_Store`).
- Можно держать глобальный `~/.gitignore_global` и подключать через
  `git config --global core.excludesfile`.
